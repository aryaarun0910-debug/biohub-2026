Host Baseline Method Explained TemporalUNet3D + SimpleNodeTransformer — how 3D+time cell tracking works

This document breaks down the Kaggle host's tracking_cellmot baseline (the unet_transformer method) end to end — from the 3D+time microscopy volumes, through detection and linking, to the final track graph, covering both inference (Part I) and training (Part II). The focus throughout is on how the "time" dimension actually gets into the model and gets fused via attention, and how the model learns all of this from sparse annotations. (This repo is a fork of this architecture — our A/B experiments share the same backbone and differ only in training data / loss / resolution.)

1Input data shape

Each video is a 4D array (T, Z, Y, X):

AxisMeaningTypical size
TTime frames (time-lapse)~100 frames
ZDepth slices64
Y, XIn-plane resolution256 × 256

Voxels are anisotropic: the Z spacing is ≈ 1.625 µm, roughly 4× coarser than the Y/X spacing of ≈ 0.406 µm. This anisotropy affects the model design throughout the pipeline (e.g. the NMS suppression radius is specified in physical µm and then converted into a different integer voxel kernel size per axis).

2End-to-end pipeline overview

Two independent neural networks working in sequence: the detection network turns the image into "which cells exist in this frame", the linking network connects the cell sets of two adjacent frames into tracks, and finally ILP picks a single, globally consistent, flow-conserving subset out of all candidate links.

3Temporal sliding window — how the time axis is "chewed" through

The model does not ingest the whole ~100-frame video at once. Instead it uses a sliding window of width W=2 frames, sliding forward with stride = W−1 = 1, so that every adjacent pair (t, t+1) is covered exactly once:

Every window goes through the same U-Net; the model sees "this frame" and "the next frame" as two 3D volumes, and inside the network per-voxel temporal self-attention lets the two frames see each other (see section 5) — this is how the model learns "where this signal should appear in the next frame", rather than matching things up afterwards with heuristics.
Why W=2 and not longer? Per-voxel temporal attention scales quadratically with W (every voxel attends to the other T time steps at the same position), and in this microscopy data cell motion mostly happens between adjacent frames; W=2 covers the minimum time span needed for "detect + link" while keeping memory/compute affordable.

4TemporalUNet3D detection backbone

Input is a pair of frames (B, T=2, C=1, Z, Y, X); output is a feature map of the same shape (B, T=2, C_feat, Z, Y, X). The architecture is a standard 3D U-Net (encoder downsamples stage by stage, decoder symmetrically upsamples with skip connections), but a "temporal attention" block is inserted after every encoder stage:

Every encoder stage: conv block → temporal attention (stage 0 skips it, replaced by Identity, since full-resolution attention is too expensive). The decoder symmetrically upsamples and concatenates the matching encoder-stage features via skip connections. A final 1×1×1 convolution collapses the features into a single-channel detection logit (one "is this a cell centre" score per voxel).

5Per-voxel temporal attention — the real "temporal fusion" mechanism

This is the core of how the whole architecture handles the time dimension. The input is (B, T, C, Z, Y, X); the trick is to flatten "spatial position" into the batch dimension, so that every voxel independently runs self-attention over its own time series (length T):

The key intuition: this is not "flatten the whole 3D volume into one vector and then compare across time" — instead, features at the same spatial coordinate at different time steps attend to each other. That means the model learns, at every location, whether the signal here is related to the signal at the same or nearby location in the next frame. This is exactly what replaces classical optical-flow / independent per-frame detection: temporal information is folded into the features already at the detection stage, rather than being aligned afterwards with heuristics.
The actual reshape path in code:
x: (B,T,C,Z,Y,X) → (B,T,C,S) → permute → (B·S, T, C), where S = Z×Y×X.
After attention, it's reshaped back to (B,T,C,Z,Y,X), with a residual connection x + attn_out preserving the original spatial features.

6From heatmap to cell coordinates — max-pool local-maximum NMS

The detection head outputs a continuous heatmap (one logit per voxel); this needs to be turned into a discrete list of "there is a cell centre here" coordinates:

Both conditions must hold for a detection: it must be a local maximum (implemented via 3D max-pool: it's no smaller than any neighbour) and its confidence must be high enough (a sigmoid probability threshold). The NMS suppression radius pool_kernel_um is specified in physical microns, then converted per axis into a different integer voxel kernel size using voxel_size (the anisotropy) — ensuring "only one peak survives within 3 microns" is isotropic in physical space, even though the voxels themselves are not.

7Positional encoding — telling the linking network "where this node is"

Each detected coordinate (t, z, y, x) is first normalised to [0,1] independently (dividing by that axis's total length), then mapped into a high-dimensional vector with sinusoidal positional encoding (like the original Transformer paper's encoding): 

for each axis a in {t, z, y, x}:
    norm_a = a / image_shape[a]                     # normalise to [0,1]
    freqs  = 2^[0, 1, ..., pos_embed_dim/2 - 1]      # octave sequence
    embed_a = concat( sin(norm_a * freqs * pi), cos(norm_a * freqs * pi) )

final positional feature = concat(embed_t, embed_z, embed_y, embed_x)   # 4 axes x 8 dims = 32 dims

This positional vector is concatenated with the "appearance feature" extracted by the U-Net (the feature-channel values at that coordinate) and fed into the linking network together — so each node's representation is "what it looks like" + "where it is in space-time".

8SimpleNodeTransformer — cross-frame linking

The linking network has to answer: is "node i in frame t" the same cell as (or does it divide into) "node j in frame t+1"? The mechanism is bidirectional cross-attention:

Every block lets frame-t nodes look at frame-t+1 nodes (cross-attention), while frame-t+1 nodes simultaneously look back at frame-t nodes; after N such alternating layers, both sides' representations have absorbed "where the other one is and what it looks like". Finally, for every pair (i,j), a pairwise score is computed: the two updated features plus their relative spatial displacement are fed into a small MLP to get a single logit — the raw confidence that "i turns into j in the next frame".
Where do divisions come from? There's no dedicated division detector — as long as max_children_per_node ≥ 2 is allowed (or the ILP assigns a cost to division rather than forbidding it outright), a parent-cell node can simultaneously connect to two child-cell nodes. Division is modelled as graph topology (out-degree = 2), not trained as a separate classifier.

9Global ILP solving — from candidate edges to final tracks

The transformer gives a probability for every possible (i,j) pair, but greedily accepting edges highest-probability-first is short-sighted and can leave later nodes with no sensible choice. The host baseline uses integer linear programming (ILP) to solve for a globally optimal set in one shot:

ILP termMeaningHost's value
edge_weightThe "benefit" of picking an edge = negative weight on the edge probability (higher probability, lower cost)−1.0 × P(edge)
appearance_weightPenalty for a node "appearing from nowhere" (no parent)0.1
disappearance_weightPenalty for a track "disappearing" (no child)0.1
division_weightPenalty for allowing a division (out-degree=2); lower encourages more divisions1.0

The solver (SCIP, wrapped via ilpy/tracksdata) finds the edge subset that minimises total cost under constraints such as flow conservation — guaranteeing the selected set of tracks is globally consistent (no node gets claimed by two mutually exclusive "locally best" choices at once). The host's own notes record this step lifting the score from a greedy ~0.73 to ~0.79.

10The whole pipeline in one figure

Left to right: the temporal window goes through the temporal-attention U-Net to produce per-frame heatmaps and features → NMS extracts coordinates → features are indexed at those coordinates and combined with positional encoding → the cross-frame transformer scores every candidate link → ILP selects the final, globally consistent track graph (divisions included).

Part II — Training how the same model learns detection and linking from sparse annotations

Part I covered "how a trained model runs at inference time"; this part covers how it gets trained — the two networks (detection U-Net, linking transformer) share a single forward pass and are trained end to end together, with a loss for each of the two sub-tasks. Sparse annotation is the biggest constraint: only a small fraction of cells in each video are manually annotated, and the rest are neither positive nor negative examples — the training loss must carefully apply supervision only where it's confident, and either ignore or use a weak prior (background statistics) everywhere else.

T1How training data is fed to the model — two sampling modes

Each training sample is still a pair of adjacent frames (t, t+1), but a whole video (Z=64, Y=256, X=256) is too large to repeatedly fit into GPU memory in full batches. This repo supports two sampling modes:

Mode A: downsample (host-style)

A strided read shrinks the whole frame directly (e.g. 1/4 along each axis). The shrunk frame is small enough to fit entirely into the network in one pass, with no cropping needed. Coordinates are divided by the same downsample factor.

Mode B: patch (full resolution)

The image is not shrunk; instead MONAI's RandCropByPosNegLabel crops a small patch at full resolution (e.g. 64×128×128, with Z taking the full depth).

Negative-patch cropping is essential: if training only ever used positive patches (always centred on an annotated cell), the model would never see what a large empty region looks like, and would detect almost nothing under full-frame inference. Mixing in ~30% background-centred negative patches forces the model to also learn to recognise empty space.

T2Sparse annotations → supervision targets

The annotation data only records "this cell ID is at this coordinate in frame t" and "this cell ID becomes this ID in frame t+1" (a sparse set of node/edge annotations — not every cell is annotated). During training this sparse annotation set must be turned into two targets:

compute_gt_transition_matrix: builds a hash table of the annotated node IDs in frames t and t+1, walks the annotated edge table, and sets a 1 at the corresponding (row, col); everything else is 0. Division (B connects to both B1' and B2') naturally shows up as "one row with two 1s" in this matrix — no separate division label is needed.
Why can't every 0 in the matrix be treated as "these two cells are definitely not the same"? Because the ground truth is sparse — plenty of real cells were simply never annotated, and their coordinates aren't even in coords, so they don't qualify to be counted in the loss at all. The linking loss (T4) therefore only computes over "rows or columns that have at least one annotation"; unannotated cells never participate in the loss, avoiding mistaking "unannotated" for "negative".

T3Detection loss — two variants

The detection head outputs one logit per voxel; the supervision signal is "is this voxel an annotated cell centre", but positive voxels are extremely sparse (~1e-5 of all voxels). This repo provides two detection losses, switched by whether gaussian_sigma is > 0:

Both are computed in fp32 (under bf16 autocast, the manual clamp(p, ..., 1-1e-6) gets rounded up to 1.0, so log(1-p)=log(0)=-inf → NaN — a bug we actually hit in practice). The Gaussian variant bakes "close enough counts" tolerance directly into the loss, making training more stable, but it also means the model's learned localisation precision is affected by the gaussian_sigma hyperparameter — which is exactly why our A/B experiments need a different det_threshold to get their best scores (the host's single-voxel version is used to "one sharp unique peak", while our Gaussian version's peaks are inherently blunter).

T4Linking loss — computed only over "annotated" rows/columns

The linking loss operates on the GT transition matrix built in T2, but out of the whole N×M matrix, only positions where "this row/column has at least one annotation" can be trusted; the rest (where neither end is annotated) are fully masked out:

compute_loss: softmax(dim=0) (row-wise — allows one frame-t node to connect to multiple frame-t+1 nodes, i.e. division, but disallows multiple frame-t nodes merging into one frame-t+1 node) first turns the edge logits into probabilities; the focal term (1-p_t)² makes cells the model has "already learned" contribute less gradient, concentrating training effort on the still-hard examples; finally the average is taken only within the active_rows | active_cols mask.

T5The full training forward pass in one figure

Both sub-tasks share the same U-Net forward pass (UNetNodeTransformer.forward, a single forward that's DDP-compatible); the detection loss and linking loss are summed into a total loss, and a single backward pass updates both networks' weights at once — the quality of the detection features directly affects what the linking task has to work with, so the two are learned end-to-end together, not by training a detector first and a linker separately afterwards.

T6Checkpointing and early stopping

At the end of every epoch, the real official score is computed using the standard recipe (5 test videos, full frames, ILP linking); whenever the score hits a new high, a checkpoint is saved (edge_predictor_best.pth). --patience N adds early stopping: once the score has gone more than N consecutive epochs without a new high, training stops — this avoids burning compute once the run has plateaued or started overfitting.

SituationBehaviour
Score hits a new highSave checkpoint; epochs_since_improve resets to 0
Score does not improveepochs_since_improve += 1; stop training once it exceeds patience
--patience 0 (default)Early stopping disabled; runs the full number of epochs
