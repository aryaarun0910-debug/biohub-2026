Motion-compensated DAXI accumulation pilot (2026-07-14)

Design corrections versus daxi_accumulation.py:
- positive tubes follow the GT lineage (oracle motion upper bound);
- controls are cached low-threshold DAXI peaks, not uniform background;
- paired controls receive the same displacement pattern as the positive tube;
- patch inference evaluates queried locations instead of thresholded cached peaks.

Results:
44b6_0113de3b: pairs=3 single_AUC=0.5000 static_AUC=0.6667
                  GT_motion_AUC=0.6667 delta_motion_vs_single=+0.1667
6bba_05db0fb1: pairs=55 single_AUC=0.0283 static_AUC=0.2225
                  GT_motion_AUC=0.1921 delta_motion_vs_single=+0.1638

Interpretation:
- 44b6 is underpowered (n=3) and cannot support a fold conclusion.
- On the adequately sampled 6bba crop, oracle GT-motion accumulation did not improve
  over static accumulation; it was lower by 0.0304 AUC.
- Absolute single-frame comparisons are confounded because controls were matched using
  cached full-volume responses while evaluation used patch responses. This explains why
  center-frame AUC was far from 0.5 and prevents treating delta-vs-single as clean.
- Static and GT-motion scores use the same paired events and inference path. Their direct
  comparison provides no evidence for a motion-compensation advantage in this pilot.

Verdict: negative pilot. Do not claim this proves every learned temporal model is
impossible, but the proposed cheap falsification has not exposed a credible mechanism
for a large track-before-detect program. A further run would require patch-response-
matched controls and substantially more 44b6 crops before any stronger conclusion.
